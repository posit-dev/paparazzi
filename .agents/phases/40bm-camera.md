## Mechanism (signed off)

- `R/camera.R` exports `pz_camera(ctx, target = NULL, ..., zoom = NULL, pad = NULL, duration = NULL)` and `pz_camera_reset(ctx)`; add `tests/testthat/test-camera.R`, roxygen-generated `man/` and `NAMESPACE`, and the `_pkgdown.yml` reference entry if one exists. Both return `invisible(ctx)` immediately when not recording, before target lookup. During recording, resolve target through existing scope/locator union (`frame_content_box()` / `el_rects()`), error if there is no target or scoped element, apply `check_pad()` with default 24 CSS px, validate zoom (>0) and duration (>=0). No page-side camera state or changes to screenshot/stage/keys. Use the page's child loop `pump_loop(page$child_loop, seconds)` exactly as cursor glides do, so poll captures and screencast events are delivered throughout the move. No new timer or capture queue.
- Recorder (`R/record.R`) owns an ordered list of camera moves, not pixel frames: each move has `from`/`to` video times from `rec_vt()`, a **padded target rectangle in absolute page CSS px** (or home for reset), optional explicit zoom, and cubic ease-in-out; home before the first move is implicit. Calculate the `from` shot at the call's current video time (including an interrupted prior move), then pump to `to`. Hold/pause-aware `rec_vt()` governs the timeline. A subsequent record start makes a fresh recorder, so no prior camera survives. No output-shaped data is stored on the page.
- Home keeps the legacy **viewport-relative** crop in CSS px from `record_crop_box()` (no translation by scroll), or the full viewport when unframed. `when = "start"` and `when = "stop"` retain their existing measurement times and start context. Shots alone are padded page-coordinate target rectangles measured with the call-time scroll. Reset is always producible, including after scrolling. Preserve the existing `record_output_spec()` alignment and `scale`: camera changes only the source crop; every output tick is scaled to the existing aligned home output `width`/`height`, including for explicit `scale` and both capture methods. For stop-time home, keep padded target boxes (not pre-clamped shots) so final aspect/fit/clamp is determined at stop; use a provisional current home geometry only to estimate an automatic move duration. No changes to the legacy no-camera encode path.
- Resolve target shots against the final home at stop; `zoom = NULL` fits the padded target to home aspect and limits fitted magnification to the **actual capture pixel density relative to CSS viewport** (poll DPR, screencast often 1 even on a DPR-2 page). Interpolate the resolved page-coordinate shots (center and log zoom, cubic easing), then at each output tick subtract its captured scroll origin, grow to home's aspect and clamp inside the viewport-relative home. Offscreen shots degrade to the nearest in-home region; never reject a shot because it is outside the current viewport. If interpolation-before-scroll conversion proves impossible, report the conflict instead of adding a new mechanism. Explicit zoom is `home_width / zoom`, centered on the target and similarly clamped; values below 1 resolve to home (no region outside home). Warn via `cli` **once per recording** if explicit zoom exceeds capture density, but do not cap it. Reset targets the full home. Default duration uses `d = center_distance / home_diagonal + 0.5 * abs(log2(zoom_to / zoom_from))`, clamped `0.66 + 2*d` to `[0.66, 2]`; explicit duration overrides it. Interpolate centers and log(zoom) with cubic ease-in-out (`4u^3` in, `1 - 4(1-u)^3` out); end values stay pinned. At encode, evaluate all output ticks on the *source* video timeline (`ticks_to_vt()` across holds, adding back `rec$times[[1]]` after resampling's normalization), so a recording hold freezes movement instead of advancing it.
- For every **accepted** frame, retain its captured viewport origin `(x,y)` alongside `rec$times`/`rec$files`; retain the first accepted frame's CSS viewport width for pixel-density conversion. Poll stores `cssVisualViewport.pageX/pageY` from the same `getLayoutMetrics()` response used for its clipped PNG (`max(pageX,0)` etc. are the actual clip origin). Screencast retains `frame$metadata$scrollOffsetX/Y` and `deviceWidth`; verify these against a live scrolled Chrome capture before relying on them. The stop-time and resume/hold snapshots use the poll metadata path. `record_resample()` returns output ticks' `vts` and `index` as well as files: repeat the matching scroll metadata when frames are repeated, with no extra CDP calls. Before generating filters, convert each interpolated page shot at each output tick to a viewport crop by subtracting that tick's *captured clip origin*, grow/clamp within home, then multiply by that source PNG's pixels-per-CSS-px. Coalesce stationary runs, especially when there is no scroll. Mixed frame sizes / viewport resize are separately tracked in kata 62g5; do not claim to repair legacy framed resize here.
- MP4/WebM camera path: four floating-point corner expressions for `perspective=sense=source:eval=frame:interpolation=linear`, keyed by av's 1-based `in` tick, followed by `scale=<aligned home output dimensions>,format=yuv420p`. At encode, evaluate each output tick's eased shot, scroll and clamp in R; serialize numerical corner runs with **balanced** `if(lt(in,...))` expression trees (coalescing identical consecutive values), rather than nesting once per tick in a deep linear chain. This preserves cubic/eased center and log-zoom interpolation without approximating coordinates between output ticks. For changed source pixel density, test the generated corners against each indexed PNG and stop on unsupported mixed-size inputs rather than applying the first PNG's density silently. Probe a ~50-move real encode **early**, before full encode integration, for parser/length and decoded positions. If the filter cannot represent it, STOP with measurements; do not design a chunked encode. GIF camera path uses the **same** perspective/scale chain with `format=rgb24`, `av::av_encode_video(..., codec="png", output=.../camera-%04d.png)` then `gifski::gifski()` with exactly the first `n_ticks` PNGs (av emits an extra terminal frame in the spike). Keep the current static GIF PNG crop path unchanged: static-crop migration is a separate optimization, not necessary to deliver camera, and avoids changing existing GIF behavior.

## Escalation and decisions

- Home is viewport-relative, not page-relative. A scrolled-away shot clamps to the nearest region of home. `when = "stop"` resolves against the final home; automatic duration estimates against a provisional home measured at start, falling back to full viewport. Leave a short code comment explaining that approximation.
- If live screencast scroll metadata or ~50-keyframe expressions fail, STOP and report measurements. No changes to device init/restore, timer, queue, display-frame storage, or ordering flag to work around them.
