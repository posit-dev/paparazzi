# Annotation core (gdjm)

Requirements: kata gdjm; `.agents/SPEC.md` § Camera, annotations, and captions (Annotations), § Cursor and staging, § Recording, § Framing; rationale on kata 1a3m. Reveal spike 3hzw confirms shadow-root animations work; its discrete-mask wipe recommendation belongs to a later mark/reveal phase, not this fade/none slice.

## Mechanism decisions (for sign-off)

- `R/annotate.R` exports `pz_annotate(ctx, target = NULL, ..., type = "box", label = NULL, pad = NULL, reveal = NULL, id = NULL, color = NULL, font_family = NULL, font_size = NULL)` and `pz_annotate_clear(ctx, id = NULL, ...)`, both returning `ctx` invisibly. This phase accepts only `type = "box"` and `reveal = "fade"/"none"` (`NULL` defaults to `"fade"` for boxes); unsupported types/reveals fail explicitly. `target = NULL` uses the pinned current scope or `document.body` at root, as existing target resolution does. `label = TRUE` numbers matches; a scalar string/number repeats on each; `pad` follows `pz_frame()`'s scalar/four-side CSS-pixel convention, default 0. Validate inputs using existing checkers/cli. User-supplied ids are nonempty strings except the reserved `"spotlight"` and `"caption"`; clear accepts those reserved ids for future single-slot types. No id generates an opaque per-page monotonic id (also clearable via clear-all).
- `R/annotate.R` holds the JS boot/draw/sync source and thin page-scoped *semantic* registry (ids, locator recipes for navigation, styles, label/pad/reveal; no DOM nodes, geometry, pixels or rendered markup). Runtime element references live only page-side in a `Map<id, {elements, nodes, reveal, ...}>` attached to the annotation layer. Resolve once with `loc_resolve(ctx, target, multiple = "all")` (scope-aware, auto-waiting), then use `Runtime.callFunctionOn` on its remote array to pass actual `Element` references to JS without serializing rectangles; release the transient remote array afterwards. Commit the R navigation recipe and re-register the new-document script only after JS draw succeeds; a failed draw leaves the prior id intact. One id groups all matches; replacing it removes the whole old group before inserting its new set. Do not retarget already attached elements after ordinary DOM replacements: disconnected elements hide until explicitly reannotated.
- Under the existing `#paparazzi-overlay-root` open shadow root, create a single `.pz-annotations` fixed, pointer-events-none, aria-hidden layer, with one box per match and optional text badge; explicit stacking puts it **below** `.pz-cursor` (and inspect outlines independent). Use safe `textContent` and style properties for labels/colors/fonts, never innerHTML from user input. Like the cursor, counter-zoom the layer against computed `<html>` zoom so viewport `getBoundingClientRect()` coordinates align with CSS pixels. `R/resolve.R` already excludes the host; shadow descendants cannot be matched by page `querySelectorAll`. Neither `pz_find()` nor element unions/frame geometry include these boxes. Inspect outlines remain `.pz-inspect` and alone are hidden by `overlay_hide()`; annotations remain visible in stills and recordings.
- The page-side `sync()` reads every connected element's `getBoundingClientRect()`, applies the pad and sets fixed box coordinates/size; disconnected targets hide their box and badge. Call `sync()` immediately on draw/replacement and during navigation boot, then schedule one `requestAnimationFrame(sync)` chain while the Map is nonempty; clearing the final entry cancels/stops it. This *only mirrors layout before paint*; it does not wait, sequence R actions, store a frame or drive capture, so it is the specifically approved exception to the timer tripwire. For a synchronous still after a scroll/layout change, `screenshot_capture()` calls page-side `sync()` immediately before `Page.captureScreenshot` (including `pz_inspect(show = "screenshot")`); the loop alone is insufficient when no rAF has fired yet. No new R timer, queue, or second ordering flag.
- Fade uses page-side WAAPI opacity (about 250 ms), reversed on clear; `none` is immediate in either direction. When `stage_recording(page)` is true, draw/clear/replacement pump `pump_loop(page$child_loop, duration)` to capture the animation; otherwise cancel/skip animations and apply the final state immediately, including when a recording is paused (consistent with `stage_recording()`). Finish removal in the page-side animation completion callback; after the R pump, explicitly finalize cleared ids synchronously so the last box cannot survive a delayed animation callback and clear-all leaves no loop. Navigation reinstates current annotations without replaying reveal. Avoid extra animation timers and promises that block CDP/R.
- On navigation, references from the old document die. Preserve annotations across recordings and **re-inject root-context annotations across navigation** by maintaining a declarative locator recipe for each root target in the R page registry and updating one `Page.addScriptToEvaluateOnNewDocument` registration after draw/clear (the cursor's established mechanism). At `DOMContentLoaded`, boot the layer and re-resolve each recipe *once* in the new document; if no matches exist yet (e.g. late-rendered SPA), keep the id hidden until explicitly reannotated rather than running a selector polling loop. Capture navigation does not promise waiting for late client-side markup. Never persist a rectangle or blindly reuse an old objectId. A scoped context is a pinned set and cannot be meaningfully reconstructed in a new document: its annotation survives recordings but on navigation is re-injected as hidden, until explicitly reannotated from a fresh scope. Root `target = NULL` rebinds to new `document.body`. The boot source is declarative state, not display-shaped content. Ask coordinator whether this scoped-navigation limitation needs a different contract before implementation.
- `R/stage.R`: add `annotate_color` (CSS color string), `annotate_font_family` (CSS font-family string), `annotate_font_size` (positive CSS px) to `pz_stage()` overrides/defaults, with explicit `NULL` resetting them. Resolve a mark's NULL style arguments at call time to page-stage defaults/built-in fallbacks (e.g. high-contrast warm border and badge, sans-serif, 14px), so later stage changes affect only future annotations. Change `R/screenshot.R` only for the immediate geometry sync; inspect's hide/restore already targets `.pz-inspect` alone. Avoid `R/record.R` (another agent owns it). Generate `man/` and `NAMESPACE` with `btw pkg document`; add the new API to `_pkgdown.yml` if reference index is explicit.

## Red-first and gates

- In `tests/testthat/test-annotate.R` use real Chrome fixtures: box draws at target bounds with pad/label and style fallback, multiple matches in one id, replacement loses old matches, clear(id)/clear(all) with reserved-id behavior; scoped target/root NULL; detached target hides. Assert page scroll, inner overflow scrolling, fixed header, and a layout shift using observed overlay rects (no fragile pixel snapshots). Assert that a screenshot taken *immediately* after a synchronous layout change contains correctly placed annotation ink but no inspect outlines; test both full-viewport and target-framed still. Navigate to a second HTML page with matching selectors and assert boot rebinds visible boxes; unmatched selectors hide, and a scoped pinned target does not remap accidentally. Verify `pz_find()`/element geometry ignore the overlay. No recording: fade requested produces no animation and returns promptly; while recording: verify fade-in and reverse clear leave captured frames/intermediate opacity before settled final frame (both poll and screencast where practical). First run a focused existing cursor/screenshot/stage harness green, then add discriminating red tests before production; record FAIL/WARN counts.
- Target tests: `.agents/chrome-lock.sh btw pkg test -f 'annotate|stage|cursor|inspect|screenshot|resolve|nav|record' --reporter minimal` (break into filters if runtime warrants it). Run `btw pkg document`, `air format --check .`, `jarl check .`. Document failures and reported FAIL/WARN/SKIP/PASS; commit in small signed conventional commits with `Refs: kata gdjm` in body. No merge, push, roborev request or issue close here.

## Escalation / open question

Stop before changing emulation/device-metrics init/restore, introducing an R-side timer/queue/ordering flag, saving rendered content or adding a guard for a guard. **Coordinator decision requested:** does the spec's “re-injected after navigation” require scoped pinned annotations to find newly matching elements across navigation? That would change the existing pinned-scope identity contract. Proposed boundary: only root locators rebind; scoped entries stay hidden. If all annotations must rebind, agree on a declarative scope reconstruction contract first.
