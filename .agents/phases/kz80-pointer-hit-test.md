# Pointer press-point hit testing (paparazzi#kz80)

Signed off:

## Problem and mechanism

`el_pointer_point()` in `R/actions.R` (around lines 372–422) scrolls the element inside `pz_poll()`, then accepts a visible, non-empty bounding box. `dispatch_click()` subsequently sends real CDP move/press/release at the returned center. An overlay or fixed header can occupy that center without changing the target's visibility or box; the action succeeds after delivering input to the obstruction. `pz_click()`, `pz_hover()`, targeted `pz_type()` (and the scoped type path when it clicks to focus), and `pz_drag()`'s source use this same point. `pz_select_text()` instead creates a DOM Range and Selection (`select_text_js`); it does not dispatch a pointer drag, so it is out of scope for this change. Keyboard-only type-with-existing-selection is also out of scope.

Replace/extend `pointer_actionable_js` to return a structured probe from the **same resolved element handle**: visibility, rect/center, and the result of a reusable JS hit-test predicate at a supplied point (default: computed center). After `stage_scroll_into_view()` on each `el_pointer_point()` poll, compute the candidate center in viewport CSS pixels (`getBoundingClientRect()`), call `document.elementFromPoint(x, y)`, descend through *open* `shadowRoot.elementFromPoint(x, y)` while possible, and accept when the deepest hit is the target or belongs to its composed descendant chain (walk `parentNode`, crossing `ShadowRoot.host`; a target which is itself a shadow host is accepted). Return raw obstruction fields (`tagName`, `id`, `classList`) for diagnostics; format them only at error time as compact `tag#id.class1.class2`, or use `<none>` for an off-viewport center. A `pointer_hit_test` JS fragment/helper should be callable from a later destination-point probe (paparazzi#8cz1) without duplicating shadow handling; this issue only checks the **source** after its final scroll. The destination's existing `dest_point_js` re-probe remains unchanged here: its target can shift when the source scrolls, and destination obstruction/retry belongs to 8cz1.

The *existing* `pz_poll(timeout = ctx$page$default_timeout, loop = ctx$page$child_loop)` retries when hit testing fails; no separate clock, queue, or ordering flag. Track only the last raw obstruction fields in R for a timeout report, never a preformatted display string. On expiry, translate the poll's timeout into a `paparazzi_error_timeout` with a specific subclass `paparazzi_error_obstructed`, naming the target description, obstructing element, and elapsed/default timeout; preserve the existing timeout behavior for hidden/zero-sized targets, and do not turn unrelated errors into obstruction errors. Example: `Timed out after 0.5s waiting for #save to receive pointer events; blocked by div#modal.scrim.` Build the error with `cli::cli_abort()` and retain the original call. The poll should record the **last failure reason**, clearing an earlier obstruction if a later probe fails visibility/size; `pz_poll` itself should not change.

Coordinates: `getBoundingClientRect()`, `elementFromPoint()` and CDP mouse dispatch use CSS viewport points, not screenshot pixel coordinates or document `scrollY` offsets. The screenshot recorder clips to `cssVisualViewport` (`.agents/phases/9tdp-recorded-click-scroll.md`), but that clip is for captures, not a coordinate transform for pointer dispatch. Include a zoom/scrolled-viewport test if current browser behavior confirms the coordinate space; a center outside the visual viewport should fail as `<none>` rather than silently dispatch. CSS selectors resolve with `querySelectorAll()` from `[document]` or a pinned scope (`R/resolve.R`), not into iframe documents; an iframe is only a top-level element, not a selectable descendant. No frame-specific coordinate transform is proposed. `elementFromPoint()` correctly skips `pointer-events:none` overlays; a `<label>` itself should be accepted as the target (as should its descendants).

## Alternatives and tripwires

- Testing visibility, clipping, `elementsFromPoint()` overlap, or `getComputedStyle(pointerEvents)` instead of the actual top hit does not prove the event receiver; in particular a pointer-events-none overlay must *not* block.
- Moving the pointer by a retry offset to find some exposed point changes the action's documented center and could mask an obstructed press; do not do it.
- A standalone sleep/retry loop conflicts with the existing auto-wait budget. A fresh remote handle or per-frame JS init script adds complexity and cannot resolve the current document hit more accurately.
- Staging's scroll already occurs inside the poll before rect/hit-test. The cursor glide runs after `el_pointer_point()` and can permit app layout to change before CDP press, as can any synchronous-to-asynchronous gap; adding a second post-glide guard for the first guard or capture/input ordering flags would cross the project's guard-for-a-guard/ordering tripwires. Do **not** implement such guards under this issue; report a reproducible race for separate direction if found. Existing capture/input DPR-2 remapping (9tdp) is separate: a DOM hit-test cannot correct Chrome remapping otherwise-correct dispatch coordinates.
