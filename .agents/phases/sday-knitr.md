# Knitr integration — phase note

## Research and API decision

- `knitr::knit_print()` processes the *visible result of each top-level R expression*, not intermediate values inside a pipe. Its vignette recommends a method returning `knitr::asis_output()` and accepting `options`, `inline`, and `...` as appropriate. See `btw docs vignette knitr --name knit_print` and [knitr's vignette](https://cran.r-project.org/web/packages/knitr/vignettes/knit_print.html).
- `knitr::include_graphics()` returns an object for top-level evaluation; `print(include_graphics(path))` inside a pipe prints the object's attributes rather than embedding the image. Knitr's author explicitly says it must be used in a top-level expression ([knitr issue 1260](https://github.com/yihui/knitr/issues/1260)). Do not use `print(include_graphics())` as a capture-time side effect.
- `magick` registers `knit_print.magick-image`. It chooses GIF for GIF input, PNG otherwise; asks `knitr::fig_path(ext, number = plot_counter())` for a numbered figure path, writes the image, and returns `include_graphics(path)`. This relies on knitr's **internal** `plot_counter()` and `in_base_dir()`, not a stable public counter API. Its special `print.magick-image` behavior during knitting writes a file but does not embed an image from the middle of an expression. See installed magick 2.9.1 source and `btw docs vignette knitr --name knit_print`.
- `fig_path()` derives `<fig.path><chunk-label>-<number>.<ext>`; without a graphics plot its default number stays `1`, even across multiple calls in one chunk (probed). Garrick chose to follow magick's internal `plot_counter()` for unique numbers; isolate this dependency and test it. `include_graphics()` supplies the external-image integration and works across output formats. A live knit probe showed a visible top-level `include_graphics()` honors caption, alt, width, and alignment; invisible output vanishes and `print(include_graphics())` prints object attributes. Verify show/hide, scale, and numbering in actual renders. See [knitr options](https://yihui.org/knitr/options/) and [Quarto figure docs](https://quarto.org/docs/authoring/figures.html).
- Quarto uses chunk `label: fig-*` and `fig-cap` for figure cross-references. Its [video shortcode](https://quarto.org/docs/authoring/videos.html) embeds local video in HTML and produces a link in other formats, but does not itself solve R Markdown. For a cross-referenced video, Quarto documents a cross-reference div rather than the ordinary image route.
- On entry, the existing screenshot/record tests were green: `btw pkg test -f 'screenshot|record' --reporter minimal` under `.agents/chrome-lock.sh`: FAIL 0, WARN 0, SKIP 0, PASS 632.

Garrick chose **top-level captures only** for automatic inclusion: a pipe should end in `pz_screenshot()` (or a recording's final call) if it should appear in the document. **A pathless capture is terminal**: in knitr it returns a printable media value instead of the context, so users cannot pipe subsequent `pz_*()` calls from that value. Explicit-path calls and calls outside knitr keep the current invisible context return. `pz_record_start()` must still return the context while recording; only `pz_record_stop()` / completed `pz_record()` can return media for an implicit path. Intermediate captures may still write files but are not promised to display. This supersedes the task's original mid-chain placement requirement; do not introduce plotting side effects or output hooks to imitate intermediate placement. Do not automatically screenshot every printed page: printing a page currently reports its browser/context state, so that would change unrelated output. Treat that as a separate proposal if needed.
