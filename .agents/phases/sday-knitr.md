# Knitr integration — phase note

## Research and API decision

- `knitr::knit_print()` processes the *visible result of each top-level R expression*, not intermediate values inside a pipe. Its vignette recommends a method returning `knitr::asis_output()` and accepting `options`, `inline`, and `...` as appropriate. See `btw docs vignette knitr --name knit_print` and [knitr's vignette](https://cran.r-project.org/web/packages/knitr/vignettes/knit_print.html).
- `knitr::include_graphics()` returns an object for top-level evaluation; `print(include_graphics(path))` inside a pipe prints the object's attributes rather than embedding the image. Knitr's author explicitly says it must be used in a top-level expression ([knitr issue 1260](https://github.com/yihui/knitr/issues/1260)). Do not use `print(include_graphics())` as a capture-time side effect.
- `magick` registers `knit_print.magick-image`. It chooses GIF for GIF input, PNG otherwise; asks `knitr::fig_path(ext, number = plot_counter())` for a numbered figure path, writes the image, and returns `include_graphics(path)`. This relies on knitr's **internal** `plot_counter()` and `in_base_dir()`, not a stable public counter API. Its special `print.magick-image` behavior during knitting writes a file but does not embed an image from the middle of an expression. See installed magick 2.9.1 source and `btw docs vignette knitr --name knit_print`.
- `fig_path()` derives `<fig.path><chunk-label>-<number>.<ext>`; without a graphics plot its default number stays `1`, even across multiple calls in one chunk (probed). Garrick chose to follow magick's internal `plot_counter()` for unique numbers; isolate this dependency and test it. `include_graphics()` supplies the external-image integration and works across output formats. A live knit probe showed a visible top-level `include_graphics()` honors caption, alt, width, and alignment; `fig.show = "hide"` suppresses the output, while `"asis"` and `"hold"` display it. Invisible output vanishes and `print(include_graphics())` prints object attributes. Explicit `include_graphics(dpi = 96 * browser_dpr)` gives a 2x screenshot its CSS-pixel width (e.g. 200px PNG appears at 100px) under either `fig.retina = 1` or `2`, unless `out.width` overrides it. Test that against actual page captures.
- Quarto uses chunk `label: fig-*` and `fig-cap` for figure cross-references. Its [video shortcode](https://quarto.org/docs/authoring/videos.html) embeds local video in HTML and produces a link in other formats, but does not itself solve R Markdown. A scratch Quarto render with top-level `asis_output('<video ...>')` *did* generate a figure caption and working cross-reference from `fig-cap`/`label`, but did not propagate `fig-alt` to the raw video; plain knitr emitted only the raw `<video>` with no caption. Video alt/accessibility and R Markdown caption behavior need an explicit, tested design; do not claim parity with ordinary figures.
- On entry, the existing screenshot/record tests were green: `btw pkg test -f 'screenshot|record' --reporter minimal` under `.agents/chrome-lock.sh`: FAIL 0, WARN 0, SKIP 0, PASS 632. A scratch Quarto render with a visible `include_graphics()` produced a figure with caption, alt, width, and a working `@fig-*` cross-reference; an otherwise identical missing-image fixture failed to render with `error: false`.

Garrick chose **top-level captures only** for automatic inclusion: a pipe should end in `pz_screenshot()` (or a recording's final call) if it should appear in the document. **A pathless screenshot is terminal**: in knitr it returns a printable media value instead of the context, so users cannot pipe subsequent `pz_*()` calls from that value. Explicit-path screenshots keep the current invisible context return. In knitr, **completed recordings, including named MP4/WebM, are terminal media**; outside knitr named recording calls keep their existing context return. `pz_record_start()` must still return the context while recording; only `pz_record_stop()` / completed `pz_record()` return media. An intermediate capture in a chain needs an explicit path (and keeps returning `ctx`); a pathless capture cannot be followed by more `pz_*()` calls. This supersedes the task's original mid-chain placement requirement; do not introduce plotting side effects or output hooks to imitate intermediate placement.

Further amendment: pathless **screenshots** at an interactive R console should write a temporary PNG and display it when printed, like magick; missing paths outside knitting **and** interactive sessions still error. This supersedes the earlier task decision that all missing paths outside knitr error. Magick's interactive print relies on `getOption("viewer")` in RStudio and its `image_browse()` falls back to `utils::browseURL()` in other consoles; both keep a PNG in `tempdir()` until R exits. Use a small preview print method over a temp file rather than requiring ImageMagick. No decision yet to expand pathless recordings outside knitting. Do not automatically screenshot every printed page: printing a page currently reports its browser/context state, so that would change unrelated output. Treat that as a separate proposal if needed.

Scope pivot/deletion pass: delete any contemplated custom `knit_print.PaparazziContext`, context-level capture state, output hook, and side-effect plotting path. The current sketch has one implicit-path helper and one interactive-preview S3 print method over a temp file, not a new capture queue or page flag.
