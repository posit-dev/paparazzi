# Text callouts (b0y7) — proposed for orchestrator sign-off

Requirements: kata b0y7; `.agents/SPEC.md` § Camera, annotations, and captions (Annotations), § Cursor and staging, § Recording, § Framing; decisions on kata 1a3m; merged `.agents/phases/{gdjm-annotation-core,m6kv-redact,mkns-marks}.md` and `R/annotate.R`. Stage 1 is this mechanism note only; no feature code before sign-off.

## Mechanism

- Add exported `pz_annotate_callout(ctx, text, ..., target = NULL, side = NULL, arrow = TRUE, label = NULL, reveal = NULL, id = NULL, color = NULL, font_family = NULL, font_size = NULL)` in `R/annotate-callout.R`, mirrored by `tests/testthat/test-annotate-callout.R`. Return `ctx` invisibly. Validate a single nonempty string `text`, `arrow` with `check_bool()`, `id` via `check_annotation_id()`, `label` like marks (`TRUE` numbers matches in resolution order; a scalar string/number repeats), CSS style inputs as marks do, and `reveal` against the existing six styles (`NULL` → `pop`). `side` uses `parse_direction(..., valid = STAGE_DIRECTIONS, arg = 'side')`: four cardinals or four diagonal corners, not center; `NULL` auto-selects **one of the four cardinals**. Reuse `loc_resolve(ctx, target, multiple = 'all')`, deferred `release_elements()`, `annotate_register_init()`, `annotate_recording()`, `annotate_call(..., 'callout', ...)` and the existing returned-duration pump. `NULL` target follows current-scope/root-body behavior. `color` defaults to staged `annotate_color`, font settings to staged `annotate_font_family`/`annotate_font_size`, resolved once at draw.
- Make only localized changes to `annotate_boot_js` in `R/annotate.R`: a `layer.pz.callout(elements, opts)` entry and a small `if (entry.callout) { ...; return; }` per-match branch in `sync()`, with a local geometry helper if needed. No second layer, Map, rAF, registry, animation builder, duration table, clear path or recorder hook. Each call creates one wrapper per matched element with a `.pz-shape` child containing the bubble and optional SVG arrow, and a label badge sibling positioned inside the wrapper's measured bounds (reserve top padding in the bubble for it so clamping keeps it visible). SVG overflow must remain visible beyond the bubble rect so the arrow can reach the target; the wrapper itself never clips the arrow. Entry uses the existing `{elements, nodes, reveal}` Map shape plus `callout:true` and an array of selected sides (one side per match). Existing `remove()` / `finishClear()` handles replacement and reverse exits; drawing returns `opts.animate ? durations[opts.reveal] : 0`. The existing shared `start()` handles all reveals: fade/pop/slide on wrapper, draw/wipe on shape; badge remains visible during draw/wipe entry and disappears at their clear start. Text and badge use `textContent` only; never HTML interpolation. Bubble: opaque charcoal (`#171717`) with white text, accent border and arrow stroke from `color` (readable even with a light/custom accent); badge uses the same dark fill and accent border with white text. Shadow DOM stays pointer-events:none/aria-hidden, below cursor; no page restyling.
- Measure each target via `getBoundingClientRect()`; measure bubble's wrapped dimensions once per `sync()` in the existing layer after setting its width constraint (no reschedule/resize observer), constrain its width to `min(320px, viewport width minus 16px)` and its height to viewport minus 16px, with overflow hidden only when even wrapped content cannot fit in that viewport. Side choice occurs once at draw, after bubble measurement: select the cardinal side with most available space (top/bottom: vertical gap; left/right: horizontal gap), preferring one where the bubble fits with an 8px gap, then deterministic order top/right/bottom/left on ties. Recompute *coordinates* every `sync()` from target and viewport but retain this chosen side to prevent flipping during scroll. Explicit diagonal sides place bubble beyond both named edges with an 8px gap. Clamp bubble coordinates to an 8px viewport inset; if target approaches an edge and clamping prevents strict on-side placement, keep it visible rather than flip. For `arrow = TRUE`, draw a stroke from the nearest point on the bubble edge to the nearest point on the target border (the arrow endpoint on the target box), with SVG arrowhead at the target; update on every sync. For `arrow = FALSE`, render only the bubble at the same gap, no SVG arrow. Disconnected/unrendered target hides its callout, like marks. This is viewport CSS-pixel geometry under the layer's existing counter-zoom; check zoom behavior before changing any device-metrics path. A bubble larger than the constrained viewport cannot show all its text; document the clipping limitation rather than extending viewport or adding a scrollable interactive overlay.
- Roxygen describes styling, side choices/clamping, labels/multiple matches (same text repeated for every match), reveal/still/recording semantics and current-document lifetime. Regenerate `man/` and `NAMESPACE` with `btw pkg document`; add the function under Annotations in `_pkgdown.yml`. Do not edit spotlight-owned code or unrelated docs/recording files.

## Escalation and questions for orchestrator

Stop before touching device-metrics init/restore, introducing a timer, queue or second ordering flag, storing display-shaped content, or adding a guard for a guard. If bubble measuring in the same `sync()` requires repeated measurement loops or a second scheduling mechanism, stop and consult. Proposed choices for sign-off: (1) permit diagonal corner sides because the shared direction vocabulary includes them, with auto restricted to cardinals; (2) when clamping defeats strict side placement, prioritize visibility over side fidelity; (3) clip content that cannot fit a tiny viewport rather than creating an interactive scrollbar or page-level expansion; (4) include an arrowhead at the target edge, despite spec wording only requiring an endpoint touching it. Are any of these choices unwanted?
