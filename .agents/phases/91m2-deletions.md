## 1. Replace the same-shot skip with a zero-length keyframe

- **Delete:** `camera_same_shot()` and its last-keyframe anchor/reset special cases in `R/camera.R`. Today `camera_move()` settles the previous move, then skips an automatic-duration call judged to be the same shot; the helper distinguishes clamped targets, reset history and scroll anchor to avoid losing the next shot's page position.
- **Replacement:** after settling and computing `from`, `to`, `home`, and current `scroll`, compare `camera_viewport(to, scroll, home) + rep(scroll, 2)` with `from`, with every coordinate difference `< 0.5`. If `duration` is `NULL` and the viewports coincide, set `duration <- 0`; otherwise use `camera_duration()`. Keep explicit `duration` unchanged. Append the normal `{start,end,box,zoom,reset,scroll}` record even for zero time. This lets a coincident viewport acquire its own unclamped target/scroll/reset anchor. `camera_at()` already gives end <= start progress 1; `camera_settle()` only pumps if remaining > 0; `camera_follow_move()`'s `last_end > arrival` check should treat the zero-length move as completed. Verify these assumptions against actual scroll/reset and in-flight cases rather than add state or a special path.
- **Tests/callers:** `tests/testthat/test-camera.R` directly calls the helper in the clamped-target/reset test: replace that test with observable `camera_move()`/`camera_at()` assertions of the stored anchor and visible viewport across a scroll. In the existing "camera calls settle earlier moves and skip non-moves" test, change only the keyframe counts after the repeated `#far` and reset calls (2→3, 3→4, 4→6 after both reset calls), and assert the added entries have `end == start`; preserve duration/pump and visible-shot assertions. Change the repeated-reset-after-scroll test's count from `n` to `n + 1`, check that the new reset has zero duration and updated scroll. Check the other repeated-target, clamped-anchor and real-scroll/reset cases from 5c357dd, ce83566, 69ae6d9 and 2832f91; do not weaken behavioral assertions. Add a repeated `pz_camera(x)`/repeated-reset recording test with `wait = TRUE` to assert video clock does not gain the automatic 0.66 s floor and no settling pump occurs, including an explicit-duration control. Amend `.agents/SPEC.md` Camera > Concurrency to say coincident automatic-duration calls record an instantaneous keyframe (including anchor/reset) but add no video time, while explicit durations still create still keyframes.
- **Verification:** write the new keyframe/clock test red against the skip (expect added entries), then run locked `btw pkg test -f camera --reporter minimal`; record exact FAIL/WARN/SKIP/PASS and confirm existing softness and follow tests still pass. Commit this item on its own.

## 4. Convert to yuv420p only after burned overlays

- **Delete:** the *early* `format=yuv420p` added by `record_output_spec()` or `camera_filter()` when a nonempty caption/key-callout overlay follows; do not remove it from the unoverlaid MP4/WebM path. `screen_filter()` already appends final `format=yuv420p` after the last overlay. Leave GIF's `rgb24` route intact, including its final conversion.
- **Replacement:** determine `burning` from caption/key-callout windows and caption mode in `record_encode()` before finalizing the base filter; pass only the needed overlay flag through the base-filter construction (`record_output_spec()`/`camera_filter()`), or equivalently remove the *trailing* base format before calling `screen_filter()` without touching crop/scale/perspective. Do not reorder rendering/windows or change `screen_filter()` beyond its owned conversion behavior. Cover both camera and non-camera base chains; VTT-only captions without key callouts must remain unoverlaid, whereas key callouts burn even in VTT-only mode.
- **Tests/callers:** add a pure filtergraph-string test in `tests/testthat/test-record.R` / `test-caption.R`: MP4 and WebM with burned captions (and with a camera) each have exactly one `format=yuv420p`, after the overlays, versus unchanged no-overlay chain; add a key-callout-only and VTT-only/no-key case if inexpensive. Preserve GIF `format=rgb24` behavior. Run decoded caption/key-callout regressions in `test-caption.R`, including their camera, WebM, GIF and stacking cases; a string-only test cannot establish composited pixels.
