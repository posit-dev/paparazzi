# Camera follows actions (paparazzi#7sq5; signed off by orchestrator)

Requirements: kata 7sq5; `.agents/SPEC.md` § Camera, annotations, and captions / Cursor and staging / Recording / Framing; camera coordinate decision in the comments on kata 40bm and `.agents/phases/40bm-camera.md`. The camera core is merged. No new capture mechanism.

## Mechanism proposal

- `R/stage.R`: add `camera_follow = TRUE` to `STAGE_DEFAULTS` and `pz_stage()` (validate with `check_bool()`, explicit `NULL` removes the override); document the recording-only behavior. Follow is a page staging preference, not recorder state. No effect on still screenshots. Generate `man/pz_stage.Rd` with `btw pkg document`.
- **Single append path, action-only hook:** `el_pointer_point()` in `R/actions.R` already finishes actionable polling and any `stage_scroll_into_view()` before calling `el_rects()` and `stage_move_cursor()`. Pass an explicit action/follow request through `stage_move_cursor(ctx, point, follow = FALSE)` (default `FALSE` keeps wheel staging and standalone cursor APIs from moving the camera). The point's `rect` attribute is the resolved target's post-scroll viewport bounding rect, not the hit-tested child. The follow hook converts it to a page-coordinate box with `page_geometry(ctx)`'s current scroll. For pointer actions that share this path (click, hover, click-to-type, drag source), do not duplicate per-action logic. A drag destination is rechecked after source scrolling; the initiating source is the follow target, not a second mid-drag shot.
- **Glide timing:** pass the action-only follow request from `stage_move_cursor()` through `cursor_show_at()` into `cursor_apply()` in `R/cursor.R`. This is where the *actual* duration (explicit entrance, ordinary glide, or first appearance) is known. Just before the cursor's command starts its animation, append one move `start = rec_vt(rec)`, `end = start + state$duration`; do not call `camera_move()` because it pumps. Existing `cursor_apply()` pumps the glide for `duration + 0.05` and is the only animation pump. First appearance without an entrance fades rather than glides: align to its existing 0.3s fade/pump. If `cursor_visible()` is false, `stage_move_cursor()` instead schedules the move over a 0.5s staged pause and pumps that pause once; nothing is drawn. If follow finds no move, don't add the pause. No timer, queue, ordering flag or extra recorder field.
- `R/camera.R`: add an internal, non-pumping `camera_follow_move(ctx, rect, duration)` returning whether it appended a move. Return without work when not actively recording, follow disabled, or already at home (including a completed reset). Obtain provisional home through `camera_home(rec, ctx)`, current page scroll through `page_geometry(ctx)`, and the interpolated shot through `camera_at(rec$camera, rec_vt(rec), home, density)`. Convert that shot to the **actual current crop** with `camera_viewport(shot, current_scroll, home, reset = attr(shot, "reset"))`, then add current scroll back to obtain a page-coordinate current shot. This matters after an intervening page scroll: the encoded crop clamps to home and is no longer necessarily the raw interpolated rect. Use the existing camera core's provisional density rule at call time (encode resolves final fit against the actual capture density). Do not compare a page rect with a viewport rect. For a home-sized current shot, no follow; an incomplete reset can still be followed if its interpolated shot is zoomed in.
- **Minimal framing:** use a 24 CSS-px margin on each target edge (the camera's default pad). If padded target is already contained in the current **clamped** page-coordinate shot (small numeric tolerance), append nothing. Otherwise grow width only if necessary to `max(current_width, padded_width, padded_height * home_width / home_height)`, capped at home width; preserve aspect ratio. On each axis, shift the old shot's low edge only enough to enclose the padded interval: clamp it to `[target_high - new_size, target_low]`; then clamp the eventual viewport-relative shot inside home by applying `camera_viewport()` with the **current** scroll and translating back. Store the resulting page-coordinate shot as `box`, with `zoom = home_width / new_width`, in the existing `rec$camera` move format `{start, end, box, zoom, reset = FALSE, scroll, follow = TRUE}`. Exclude `follow = TRUE` from the explicit-zoom softness warning: this zoom retains an existing magnification, not a requested new one, and rounding can cross the density boundary. `camera_shot()` will recover this centered rectangle from `box`/`zoom` at encode. For `when = "stop"`, the zoom is resolved against the final home at encode, the same accepted provisional-home approximation as the camera core; add a short code comment beside the append. If the target cannot fit within home, prefer the nearest legal home-sized shot; skip a move if it would not change the actual crop. Current zoom is retained for a target that fits; no automatic zoom-in. Interrupted moves use `camera_at()` at the new start time, not the previous destination. No change to `R/record.R` or `R/screenshot.R`.
- **Typing without pointer:** `pz_type(target = NULL)` at root and the scoped active-selection fast path have no pointer glide. If there is a focused/selected element, resolve its rect *after any action scroll* and call the same non-pumping follow append path, with a 0.5s staged pause only when a move was appended; when nothing is focused, no camera motion. `pz_select_text()` scrolls instantly before resolving its text target; use its post-scroll rect with that same no-glide path after successful selection. Only mutate the camera for pointer and typing actions (including `pz_select_text()`), not `pz_focus()`, programmatic value/file setters, getters, expectations, waits, navigation, or scroll commands. Describe this as "pointer and typing actions" in `pz_stage()`'s `camera_follow` documentation. Keep these exceptional call sites small; all pointer actions go through the one `el_pointer_point()` hook. No extra page-side JS state: `el_rects()` / existing geometry and focused-element read only.

## Orchestrator decisions / escalation

- Scope: pointer and typing actions, including `pz_select_text()`. Programmatic value/file setters and `pz_focus()` do not follow. First cursor appearance aligns to its existing 0.3s fade pump. If target plus margin cannot fit at home, cap at home and skip a move that would not change the actual crop.
- Follow keyframes carry `follow = TRUE` so their computed zoom never causes the explicit-zoom softness warning. For `when = "stop"`, their zoom uses the provisional home and is reinterpreted against the final home at encode, matching the accepted camera-core approximation.
- If fitting/scroll races require a second timer, queue, ordering flag, guard-for-guard, or changes to device init/restore, STOP and consult. If `cursor_apply()` needs a second pump or ordering state, STOP. Do not touch concurrent caption or annotation files.
