## Mechanism

- `R/caption.R` exports `pz_annotate_caption(ctx, text, ..., side = "bottom", color = NULL, font_family = NULL, font_size = NULL)`; validate nonempty scalar text, side (`"top"`/`"bottom"`), CSS color/family strings and positive CSS-px size using existing checkers. Return `ctx` invisibly. Keep a **single declarative caption slot** (`text`, `side`, resolved style) in `ctx$page$.__enclos_env__$private$staging_`, accessed only through `page_caption()`/`page_set_caption()` helpers. It belongs to the page, not the current document or scope; it persists through navigation and recordings. No pixel buffer, PNG path, DOM replica or image dimensions are retained in page/recorder state. Resolve style at call time so later stage changes don't retroactively restyle an existing caption. `color = NULL` always means white text, independent of `annotate_color` (the mark accent). `font_family = NULL` uses `pz_stage(annotate_font_family)` then its built-in fallback; `font_size = NULL` uses a caption-specific 20 CSS px default, not the badge-size `annotate_font_size`. Document these distinctions in roxygen.
- In `R/annotate.R`, after the existing page-side Map clear, call `caption_clear(ctx$page)` for `id = NULL` or `id = "caption"` only. The helper clears the slot and, if a recorder is active, logs the clear at `rec_vt(rec)`. Other ids do not affect captions. Neither the annotation Map nor its JS renderer knows about captions; clearing a caption does not animate or pump. A set/replacement logs `{vt, caption}` on the active recorder even when paused (pause-aware video clock); clear logs `{vt, NULL}`. At `pz_record_start()` initialize `rec$captions` to the current slot at `vt = 0` (if present) and `rec$caption_mode` from `captions = c("burn", "vtt", "both")`. Reject `"vtt"`/`"both"` for GIF up front with `cli::cli_abort("WebVTT sidecars need an MP4 or WebM recording")`; `"burn"` works for all formats. Subsequent calls at identical video times take the **last** event; paused mutations are visible on resume. Ending a recording does not clear the page slot. Events are declarative, not rendered content.
- Render **only at encode/still time**, after output dimensions are known: `caption_render(page, caption, width, height, font_scale, path)` opens a short-lived `page$chromote$new_session()` target in the same browser, with transparent html/body and `Emulation.setDefaultBackgroundColorOverride(alpha = 0)`, captures a full-output-size transparent PNG through `Page.captureScreenshot()`, and closes the target via `on.exit`. Text goes into `textContent`, never HTML. Explicitly pass the resolved font-family CSS string; page CSS and webfonts do not cross targets. Center an auto-wrapping pill with max-width ~80%, padding, translucent charcoal background and white-by-default foreground, offset from the requested top/bottom edge. Scale font size and padding by the output scale factor (final width / unscaled recording home width; for stills use captured pixel width / CSS clip width); rasterize at final pixel dimensions, not at call time. This avoids display-shaped state, stale layout and camera-resampling blur. If separate-target font parity for page-loaded webfonts is required beyond the explicit family, escalate rather than silently claim parity.
- `R/record.R`: `record_encode(rec, page)` gets `record_resample()`'s output-tick `vts`, `n_ticks` and `record_output_spec()` dimensions. Map event windows to ticks using the same normalized video-clock mapping as frames (including first/last holds, explicit holds and paused stretches); a window is `[first tick whose vt >= set vt, first tick whose vt >= next event vt)`, and the terminal boundary is `n_ticks / fps`. For events preceding the first captured vt, clamp to tick 0. Coalesce adjacent same-caption/zero-length windows; prevent stale captions after clear or replacement. Generate VTT cues from these output-timeline tick boundaries (hh:mm:ss.mmm, HTML-sensitive characters escaped, line breaks preserved) into `tools::file_path_sans_ext(rec$path) + '.vtt'`; only `vtt`/`both` write a sidecar. `vtt` does not burn; `burn` does not write a sidecar. If a recording has no captions, write a valid `WEBVTT` header for requested sidecar modes.
- For MP4/WebM `burn`/`both`, render one transparent overlay PNG per distinct caption/style/output-size into a paparazzi-owned `tempfile("paparazzi-caption-")` directory, named `caption-1.png`, etc. Extend `out$vfilter` **after** `camera_filter()`'s perspective/scale (or ordinary crop/scale), as a single av filtergraph: input chain to `[base]`, finite `movie=caption-1.png:loop=1` (bare relative filename; no escaped paths), `format=rgba`, `loop=n_ticks-1:size=1:start=0`, `setpts=N/(fps*TB)`, alpha `fade` at bounded in/out windows, then `[base][overlay]overlay=0:0:enable='between(t,start,end)'`; end with format appropriate for codec. Call `av::av_encode_video()` inside `withr::with_dir(caption_dir, ...)` when burning, passing absolute input and output paths as function arguments. No infinite movie loops (the spike hung). Probe two windows plus a camera move early, with a user output directory containing spaces and an apostrophe; if cwd-relative `movie=` still fails to parse or open, STOP and report the exact graph and error. Render captions once per distinct content and use windows for timing (separate filter source per window when necessary).
- For GIF with a burning caption, use **the same av caption filtergraph** as MP4/WebM: materialize output-size ticks via `av::av_encode_video(..., codec = "png")` with camera or ordinary crop/scale first, then caption movie/overlay/fade filters. Trim av's extra terminal PNG to `n_ticks` and pass those files to `gifski()`. GIFs without burn preserve their current paths. Only stills use R alpha blending. In `R/screenshot.R`, after `screenshot_capture()` writes the still and before returning/include_graphics, render the current caption at the resulting PNG size and blend only its nontransparent rows onto the file. This includes scoped/framed screenshots, regardless of camera position. The transparent target must not change the recorded page or its device-metrics state.
- Update `man/`, `NAMESPACE`, `_pkgdown.yml`, and roxygen on record/screenshot. Defer knitr `<track>` wiring to ks7r: this issue writes the named VTT file, but `record_knit_media()` currently copies the media to a hashed figure path and would require sidecar copying/URL wiring to expose it. Do not edit `R/camera.R`, `R/stage.R`, `R/actions.R`, `R/cursor.R`, `R/context.R` or `SPEC.md` in this issue.
