## Mechanism

- `R/caption.R` exports `pz_annotate_caption(ctx, text, ..., side = "bottom", color = NULL, font_family = NULL, font_size = NULL)`; validate nonempty scalar text, side (`"top"`/`"bottom"`), CSS color/family strings and positive CSS-px size using existing checkers. Return `ctx` invisibly. Keep a **single declarative caption slot** (`text`, `side`, resolved style) in `ctx$page$.__enclos_env__$private$staging_`, accessed only through `page_caption()`/`page_set_caption()` helpers. It belongs to the page, not the current document or scope; it persists through navigation and recordings. No pixel buffer, PNG path, DOM replica or image dimensions are retained in page/recorder state. Resolve stage style at call time so later stage changes don't retroactively restyle an existing caption. Proposed caption default foreground is white (not the box-annotation default pink); see sign-off question below.
- In `R/annotate.R`, after the existing page-side Map clear, call `caption_clear(ctx$page)` for `id = NULL` or `id = "caption"` only. The helper clears the slot and, if a recorder is active, logs the clear at `rec_vt(rec)`. Other ids do not affect captions. Neither the annotation Map nor its JS renderer knows about captions; clearing a caption does not animate or pump. A set/replacement logs `{vt, caption}` on the active recorder even when paused (pause-aware video clock); clear logs `{vt, NULL}`. At `pz_record_start()` initialize `rec$captions` to the current slot at `vt = 0` (if present) and `rec$caption_mode` from `captions = c("burn", "vtt", "both")`. Subsequent calls at identical video times take the **last** event; paused mutations are visible on resume. Ending a recording does not clear the page slot. Events are declarative, not rendered content.
- Render **only at encode/still time**, after output dimensions are known: `caption_render(page, caption, width, height, font_scale, path)` opens a short-lived `page$chromote$new_session()` target in the same browser, with transparent html/body and `Emulation.setDefaultBackgroundColorOverride(alpha = 0)`, captures a full-output-size transparent PNG through `Page.captureScreenshot()`, and closes the target via `on.exit`. Text goes into `textContent`, never HTML. Explicitly pass the resolved font-family CSS string; page CSS and webfonts do not cross targets. Center an auto-wrapping pill with max-width ~80%, padding, translucent charcoal background and white-by-default foreground, offset from the requested top/bottom edge. Scale font size and padding by the output scale factor (final width / unscaled recording home width; for stills use captured pixel width / CSS clip width); rasterize at final pixel dimensions, not at call time. This avoids display-shaped state, stale layout and camera-resampling blur. If separate-target font parity for page-loaded webfonts is required beyond the explicit family, escalate rather than silently claim parity.
- `R/record.R`: `record_encode(rec, page)` gets `record_resample()`'s output-tick `vts`, `n_ticks` and `record_output_spec()` dimensions. Map event windows to ticks using the same normalized video-clock mapping as frames (including first/last holds, explicit holds and paused stretches); a window is `[first tick whose vt >= set vt, first tick whose vt >= next event vt)`, and the terminal boundary is `n_ticks / fps`. For events preceding the first captured vt, clamp to tick 0. Coalesce adjacent same-caption/zero-length windows; prevent stale captions after clear or replacement. Generate VTT cues from these output-timeline tick boundaries (hh:mm:ss.mmm, HTML-sensitive characters escaped, line breaks preserved) into `tools::file_path_sans_ext(rec$path) + '.vtt'`; only `vtt`/`both` write a sidecar. `vtt` does not burn; `burn` does not write a sidecar. If a recording has no captions, write a valid `WEBVTT` header for requested sidecar modes.
- For MP4/WebM `burn`/`both`, render one transparent overlay PNG per distinct caption/style/output-size into a temporary encode directory. Extend `out$vfilter` **after** `camera_filter()`'s perspective/scale (or the ordinary crop/scale filter), as a single av filtergraph: input chain to `[base]`, finite `movie='escaped-path':loop=1`, `format=rgba`, `loop=n_ticks-1:size=1:start=0`, `setpts=N/(fps*TB)`, alpha `fade` at bounded in/out windows, then `[base][overlay]overlay=0:0:enable='between(t,start,end)'`; end with format appropriate for codec. No infinite movie loops (the spike hung). Test filter parser and graph length early with a two-window encode, including a camera move and a path containing spaces/apostrophes; if filter length/escaping fails, stop and report rather than implement a second encode scheduler. Render captions once per distinct content and use windows for timing (separate filter source per window when necessary).
- For GIF with a burning caption, materialize output-size ticks **before** blending: reuse camera's existing av PNG-sequence path when moving, use the ordinary av crop/scale vfilter for static captures that need scaling, and retain the existing static R crop for unscaled captures. Trim av's extra terminal PNG to `n_ticks`, as camera already does. Alpha-blend just the nontransparent caption rows/window in R at output ticks, using `png`, with a clamped ~0.25 s in/out fade (at most half of a short window); write unique PNG paths for changed opacity, reuse unmodified paths when possible, then `gifski()` as today. GIFs without burn preserve their current path. No pixel arrays retained on the recorder. In `R/screenshot.R`, after `screenshot_capture()` writes the still and before returning/include_graphics, render the current caption at the resulting PNG size and blend its nontransparent rows/window onto the file. This includes scoped/framed screenshots, regardless of camera position. The transparent target must not change the recorded page or its device-metrics state.
- Update `man/`, `NAMESPACE`, `_pkgdown.yml`, and roxygen on record/screenshot. Defer knitr `<track>` wiring to ks7r: this issue writes the named VTT file, but `record_knit_media()` currently copies the media to a hashed figure path and would require sidecar copying/URL wiring to expose it. Do not edit `R/camera.R`, `R/stage.R`, `R/actions.R`, `R/cursor.R`, `R/context.R` or `SPEC.md` in this issue.

## Escalation / sign-off questions

- **Color default conflict:** the spec calls for a white-text default pill, but also says `color = NULL` falls back to `pz_stage(annotate_color)`, whose built-in value is pink `#e11d48`. Proposed: explicit `color` wins; an explicitly overridden `annotate_color` wins; absent override use white for captions. Approve this caption-specific exception, or use pink to honor the uniform stage rule?
- **VTT on GIF:** the issue says `captions =` applies to `pz_record_start()` (including GIF), but describes sidecars next to *video*. Proposed to write VTT for GIF too when requested, with correct GIF output tick times, even though GIF players do not consume tracks. Restrict modes to video instead?
- Do not touch the protected init/restore window or add timers, queues, ordering flags, display-shaped recorder state or guards-for-guards. Escalate if target transparency, relative font loading, path escaping or long filtergraphs force one of those approaches. The camera/annotation branches own their respective files; keep the clear hook minimal.
