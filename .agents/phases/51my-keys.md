# Keystroke callouts (51my) (signed off by orchestrator)

Requirements: kata 51my; `.agents/SPEC.md` § Camera, annotations, and captions / Captions and keystroke callouts; rationale in kata 1a3m, caption precedent in kata aq35 and `.agents/phases/aq35-captions.md`, Mod resolution in kata 2sx9. Orchestrator signed off the mechanism below, with the pause rule and simplified stacking geometry recorded here.

## Mechanism decisions

- `R/stage.R`: add `show_keys` to `pz_stage(ctx, ..., show_keys)` and `STAGE_DEFAULTS` (`"none"`). Validate `"none"`, `"words"`, `"mac"`, `"both"` by `arg_match()`; explicit `NULL` removes the override as for other staged settings. Document the option. `R/actions.R`: `pz_press(ctx, key, ..., show_keys = NULL)` validates an explicit non-NULL value and otherwise reads `page_stage(ctx$page)$show_keys` **at the action**, not at encode. Keep `pz_type()` unchanged. Preserve key dispatch and per-call browser Mod lookup. Parse each spec once and use that parsed value for both dispatch and recording; only append a recorder event when there is an active, **unpaused** recorder and the effective style is not `"none"`. A press while paused dispatches normally but makes no callout: that action is cut from the video. A call without a recorder must not create persistent page state. Log only after successful dispatch, before `stage_action_pause()`; stamp `start` immediately before the first dispatch and `last` after the last dispatch with pause-aware `rec_vt()`. A vector of specs is **one** callout with ordered key groups, displayed as a sequence (for example `Mod+K → Enter`), so its last key controls expiry. Store `list(vt = start, last = last, style = style, keys = list(list(spec = original_spec, resolved = parsed), ...))` in `rec$keypresses`; initialize the list in `new_recorder()` (`R/record.R`). `spec` preserves spelling/Mod, `resolved` holds the already-parsed key and modifiers actually dispatched; no label, geometry, PNG, or font rendering is stored. If dispatch fails, there is no callout event.
- **Consecutive calls replace, never extend.** At each output tick, only the latest call whose start has been reached may be visible; it replaces the previous immediately, even inside its hold/fade. A `show_keys = "none"` call creates no replacement (so it does not cancel the previous callout). The encode-time event list describes a single ephemeral visible slot; it is not a timer/dispatch queue or an ordering flag. Within a vector call, all specs are shown in order, rather than silently losing early keys dispatched within the same output tick.
- `R/keys.R`: pure `key_callout_labels(spec, parsed, style)` converts original modifier tokens in their supplied order, plus the resolved main `parsed$key$key`, into keycap labels. Canonical aliases: words `Control → Ctrl`, `Shift`, `Alt`, `Meta`; mac `⌃`, `⇧`, `⌥`, `⌘`; both uses word labels except an original `Mod` token becomes `Ctrl / ⌘` regardless of whether the browser resolved it to Meta or Control. For words/mac an original `Mod` uses the resolved modifier. Do not invent an explicit Shift cap for implied-shift characters (`"A"`); never show the CDP control-character `text` (Enter/Tab show their key names). Use `textContent` for labels, never HTML. A bare modifier such as `"Control"` is the main key rather than a modifier token, but still uses that style's matching modifier keycap (`Ctrl` or `⌃`).
- `R/caption.R`: reuse the separate Chrome target and output-resolution CSS/transparent PNG capture. Introduce a small screen-overlay rendering/filter helper so caption and keycap sources share **one** post-camera av graph and the existing bare `movie=<owned-filename>.png` + `withr::with_dir()` path for MP4/WebM/GIF. Keep caption stills/VTT untouched. `key_callout_render(page, groups, width, height, scale, bottom_offset, path)` draws a centered, horizontally wrapping set of translucent dark CSS keycaps at the final output pixel dimensions, using `textContent`; no rendering on the recorded page. For a bottom caption, use the caption renderer's measured pill height at encode plus its bottom margin (24 × scale) and a keycap gap (e.g. 12 × scale) to compute the keycap's bottom offset. A top caption requires no displacement. Render each callout **once**, at a bottom offset computed using the tallest burned bottom caption whose window overlaps the callout's visible window; it is acceptable for keycaps to sit somewhat high if a caption changes mid-callout. When `captions = "vtt"`, no caption is burned, so keycaps stay at their ordinary bottom offset (external player subtitle placement cannot be measured). These measurements are local to encode; do not store display-shaped recorder/page state.
- `R/record.R`: map press start and last to output tick indices using `record_resample()`'s pause/hold-aware sampled `vts`, like `caption_windows()`. At each tick choose the most recent started event, stop it on replacement or at 1 s after its **last key on the output timeline**; fade only in the following 0.25 s. Explicit holds repeat source `vt`, so expire by **output ticks**, not by comparing sampled `vt` with `last + 1.25`; otherwise a frozen hold could make a keycap stay visible indefinitely. First eligible tick is fully opaque, no fade-in. Clamp windows/fades to available ticks; no overlay when the press is after the last output tick. Map event timestamps to ticks exactly as captions do: R is blocked during `pz_record_hold()`, so a press cannot happen inside an explicit frozen hold. Build caption and key overlays before encoding and chain their sources after camera/crop/scale in one filtergraph, with caption first and keycaps second, using finite movie loops and absolute av input/output paths. GIF continues through the same av PNG-sequence route whenever either overlay exists. No keycaps on stills, no changes to `R/annotate.R` or the device-metrics init/restore window.

## Escalation and sign-off decisions

Stop rather than add a timer, queue, ordering flag, buffered image/label state or guard-for-guard; do not modify init/restore. If caption height cannot be obtained from the existing renderer, or av cannot handle simultaneous caption/key sources with bare relative movie filenames, report the probe graph/error before replacing the encode mechanism. Do not edit concurrent `R/annotate.R`.

Orchestrator signed off: consecutive calls replace, a vector is one sequenced callout; stack above burned bottom captions only; explicit holds block R so presses cannot occur inside them, and event-to-tick mapping follows captions. Presses while paused generate no callout event. One key overlay uses the tallest overlapping burned bottom caption; no split overlays or mid-callout reflow test.
