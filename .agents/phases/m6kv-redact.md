# Redaction annotations (m6kv) (signed off by orchestrator)

Requirements: kata m6kv, `.agents/SPEC.md` § Camera, annotations, and captions (Annotations), § Cursor and staging, § Recording, § Framing; rationale on kata 1a3m, and the merged gdjm core / `.agents/phases/gdjm-annotation-core.md`. Redaction is an overlay, not a page style change. Stage 1 committed as c0110b8; orchestrator signed off on the decisions below before implementation.

## Mechanism decisions

- Add exported `pz_annotate_redact(ctx, target = NULL, ..., method = c("fill", "blur"), pad = NULL, id = NULL, color = NULL)` to `R/annotate.R`, next to `pz_annotate()`. Return `ctx` invisibly. Use `loc_resolve(ctx, target, multiple = "all")`, `release_elements()`, `annotate_register_init()`, and `Runtime.callFunctionOn` with the actual element array, as gdjm does. `NULL` target means current scope or root body; `pad = NULL` means zero, via `check_pad()`. Validate method with `rlang::arg_match()`, nonempty id excluding `spotlight`/`caption`, and color with `check_string()` if supplied. No R-side registry, captured image data, CSS selector recipe, or alternate overlay. Use the shared page-side Map and a new `layer.pz.redact(elements, opts)` entry point; it inserts an entry with the existing `{elements, nodes, pad, reveal}` shape and `reveal: 'none'`, so existing `clear()` / id replacement work instantly even during recording. All matches must be viable before replacing an existing id: an initial disconnected/non-rendered element has no last box and raises a JS exception through `cdp_check_exception()`, without removing the old entry. The default fill is an opaque neutral near-black (`#171717`), independent of `stage$annotate_color` (marks-only). `color` customizes fill; for blur, reject an explicit `color` rather than imply that it changes the blur. No reveal, animation or R-side pump.
- Reuse the gdjm `.pz-annotations` layer and its existing `sync()` / single rAF loop. Redaction boxes get their own class plus `position:fixed`, `pointer-events:none`; they are opaque fill boxes or `backdrop-filter: blur(32px)` boxes with transparent backgrounds. A fill box has an opaque near-black background *under* an optional colored child covering the same rectangle: transparent/invalid CSS color cannot reveal the page underneath. Set the child color through `style.backgroundColor`, never injected markup. CSS `z-index:1` on each redaction puts it above mark nodes (`auto`) regardless of draw order, while the whole annotation layer (`z-index:0`) remains below the cursor layer (`z-index:1`). Document that blur obscures rather than guarantees erasure; use fill for secrets.
- On disconnected or non-rendered targets, `sync()` must leave the redaction node **visible at its last measured box** rather than hide it (unlike marks). Apply this per entry/match, preserving the last coordinates; on reconnection resume normal geometry following. A redaction created without a measurable box errors; there is no safe last box to retain. No re-resolving after DOM replacement or navigation: the current-document Map is discarded on navigation, as in gdjm. Clear removes redactions immediately, by id or all. No new sync hook: `redact()` calls `sync()` synchronously before returning; existing `screenshot_capture()` calls `sync()` before screenshot. For poll recording, a capture whose CDP screenshot *starts after the call returns* sees the installed box; a capture already in flight may complete later with old pixels. For screencast, the immediate DOM change induces a paint with the box. Do not add timers, queues, capture barriers, or flags; if a real capture-start-after-return counterexample appears, stop and escalate instead of changing `R/record.R`.
- Roxygen documents current-document lifetime, blur's limits, instant semantics, color behavior, and returns; `btw pkg document` updates `man/` and `NAMESPACE`. Add `pz_annotate_redact` to `_pkgdown.yml`'s Annotations section. Avoid concurrent agents' source files, including caption edits in `R/annotate.R`.

## Red-first tests and gates

- Add focused tests to `tests/testthat/test-annotate.R` (mirrors `R/annotate.R`): first a red test for missing API and pixel-opaque fill on known contrasting text, both in a still and in post-call poll captures. Capture start ordering: let any already-pending capture finish, then sample subsequent recorded PNGs, without interpreting completion time as capture start. Record the red FAIL/WARN before implementing. For blur, compare known sharp black/white text pixels in PNG against unredacted baseline and check computed `backdropFilter` (`32px`); sample enough of a high-contrast text region to distinguish blurred from unmodified, without treating blur as secure for secrets.
- Test every match covered, scope/root target, pad, independent default color despite staged mark color, customized fill with alpha/invalid color never revealing the background, validation (method, id, color), shared id replacement mark↔redaction and clear(id/all) while recording, redaction above a mark drawn *later* but below the cursor, instant draw/clear without animation, synchronous still capture after layout shift, scrolling (page/inner/fixed), and disconnect/display:none retaining the last box (fill and blur) including rendered pixels. Test that an initially hidden match errors without replacing an existing id. Include a short screencast smoke test if Chrome produces a repaint reliably; otherwise report its untested capture boundary rather than a flaky assertion. Reuse the existing page fixture and bound Chrome time to a few minutes.
- Run `.agents/chrome-lock.sh btw pkg test -f annotate --reporter minimal`, then targeted seams `.agents/chrome-lock.sh btw pkg test -f 'annotate|screenshot|record|stage|cursor|nav' --reporter minimal` (split if budget requires). Run `btw pkg document`, `air format --check .`, `jarl check .`; report FAIL/WARN/SKIP/PASS. Commit small signed conventional changes with `Refs: kata m6kv` in commit bodies. Stage 2 ends with phase handoff and issue comment; no merge, push, roborev, or close.

## Escalation / sign-off decisions

Stop before changing init/restore/device metrics, adding a timer/queue/second ordering flag, storing display-shaped content, or adding a guard for a guard. In particular, no recorder change merely to prevent already-started captures from completing after the call. Orchestrator confirmed: (1) opaque near-black base below user color, including translucent or invalid colors, documented in one sentence; (2) explicit `color` with `method = 'blur'` raises a clear cli error; (3) cursor stays above redaction. Screencast smoke test is optional to stay within the few-minutes Chrome budget.
