## Mechanism decisions

- Export `pz_annotate_spotlight(ctx, target = NULL, ..., pad = NULL, dim = NULL, reveal = NULL)` in new `R/annotate-spotlight.R`; tests in `tests/testthat/test-annotate-spotlight.R`. Check context and empty dots; use `check_pad(pad %||% 0, arg = "pad")`, `loc_resolve(ctx, target, multiple = "all")` for explicit/root targets (with deferred `release_elements()`), and `scope_root(ctx)` for scoped `target = NULL` (pinned set, do not release); then `annotate_register_init()`, `annotate_call(ctx, els, "spotlight", options, ...)`, `annotate_recording()` and the existing duration/pump convention. `NULL` target retains current-scope/root-body behavior. Default `dim = 0.6`, validate finite numeric scalar in `[0,1]` (including both endpoints). Default `reveal = "fade"`; accept `"fade"` and `"none"`, reject draw/pop/slide/wipe because drawing a border, moving the viewport-wide scrim or conic-wiping it is misleading. Return `ctx` invisibly.
- Add one `layer.pz.spotlight(elements, opts)` method and one spotlight branch in `sync()` in the existing boot JS (`R/annotate.R`), leaving the concurrently edited callout method untouched. Preserve the one page-side `Map`, one rAF loop, navigation reset and `clear()`/`finishClear()` paths. Use fixed Map key `spotlight` and replace with `remove('spotlight', false)`; no R-side registry, second loop, selector recipe, or snapshot. Store `{elements:[...elements], nodes:[svg], pad, reveal}` with an explicit spotlight discriminator for `sync()`. Reuse the shared fade/none WAAPI keyframes and duration table; `draw` returns its actual entry duration, `clear` returns the reverse duration, and R pumps only while recording and unpaused. Non-recording/paused draw and clear are instantaneous. New calls replace immediately, as marks do; clearing by `"spotlight"` or clear-all removes the slot. `remove()` already accepts a fade/none node without `.pz-shape`.
- Render one full-viewport fixed SVG overlay, with black scrim at `dim` opacity and an SVG mask explicitly set to luminance mode: a white viewport rect with a black rounded rect (proposed radius 6 CSS px) for **each** rendered, positive-area padded match. Black mask rects union even when cutouts overlap, unlike an evenodd path (which fills their intersection); pixels inside cutouts are unchanged and outside darkened. `sync()` updates viewport/mask dimensions and each rect from `getBoundingClientRect()` and `pad` before paint; a disconnected/hidden or zero-area target contributes **no hole** (never retains a stale one), and reconnecting restores it. The initial draw invokes `sync()` synchronously before returning; still capture already calls layer sync. The mask rects are DOM geometry inside the page, not saved image content. Keep overlay pointer-events none and within the annotation layer, below existing marks/callouts and redactions (redactions remain opaque) and below the cursor. Proposed `z-index:-1` on the spotlight node against marks at `auto` and redactions at `1`; verify this stacking with real Chrome pixels, including a mark/redaction created before and after the spotlight. Do not modify other agents' callout code; escalate if their stacking needs coordination. Document that like other page overlays the spotlight cannot cover top-layer modals/popovers and only cuts out the target's padded border box.
- Add `man/pz_annotate_spotlight.Rd`, generated NAMESPACE export (`btw pkg document`), and `_pkgdown.yml` Annotations entry. Roxygen describes single-slot lifetime, cutout geometry/disconnection, default dim, supported reveal/recording semantics, and clear. No stage defaults or recorder changes.
