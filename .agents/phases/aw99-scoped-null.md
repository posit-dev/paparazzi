# Scoped NULL annotation target (signed off by orchestrator, 2026-09-29)

Requirements: kata aw99; `.agents/SPEC.md` § Scoping and § Camera, annotations, and captions → Annotations. Root `target = NULL` remains `document.body`; scoped `target = NULL` annotates the pinned scope root, including every match in a multi-match scope.

## Mechanism

- `target_resolver_expr(NULL)` in `R/resolve.R` always returns `[document.body]`. `loc_resolve()` does check the scope but cannot redirect that root-only NULL resolver. Marks, callouts and redactions call it directly. Spotlight already handles scoped NULL by taking `scope_root(ctx)` instead, without releasing the pinned set. Existing scoped-NULL tests for marks/callouts/redaction assert only the number of overlay nodes, so they pass while pointing at body.
- Follow `frame_content_box()` and `action_elements()`: probe `scope_root()` for NULL before resolving an explicit target; never release a pinned scope. Unlike actions (which reject root NULL), annotations use `loc_resolve(ctx, NULL, multiple = "all")` at the root to keep body behavior. Unlike frame content (which returns NULL for unscoped NULL), annotations draw on body. Explicit targets retain lazy resolution inside the scope and transient-handle cleanup.
- Extract exactly one private annotation helper in the **R-only portion** of `R/annotate.R` (before `annotate_boot_js`): `annotate_elements(ctx, target, call = caller_env())` returns `list(els = ..., pinned = TRUE/FALSE)`. For NULL, use `scope_root(ctx, call = call)`; if present, return the pinned set. Otherwise call `loc_resolve(ctx, target, multiple = "all", call = call)` and return its transient set. Each of the four annotation functions uses that helper and defers `release_elements()` only when `pinned` is false. Do not change resolver semantics globally, annotation validation, the boot JS string, or exported APIs. No roxygen change expected; document only if behavior text needs correction.
