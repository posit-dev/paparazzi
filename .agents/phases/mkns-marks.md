## Mechanism

- Change only `R/annotate.R`, `tests/testthat/test-annotate.R`, generated `man/`, and this note. Preserve `pz_annotate()`'s signature, `annotate_call()`/`check_annotation_id()`, its single page-side `Map<id, {elements,nodes,pad,reveal,...}>`, current-document lifetime, follow rAF, stacking, redaction entry, and `pz_annotate_clear()`/caption-clear semantics. `type` accepts `box`, `circle`, `underline`, `highlight`; `reveal` accepts `fade`, `draw`, `pop`, `slide`, `wipe`, `none`. `NULL` picks defaults: box → fade (backward compatible), circle → draw, underline → draw, highlight → draw (left-to-right highlighter stroke). Wipe remains available explicitly on every type. Explicit reveal works on every type. Validation remains in R, with cli messages. Existing label behavior stays: `TRUE` numbers matches in resolution order, one scalar repeats. Place badges at the padded box's upper-left, outside the shape as today; check that new shapes don't obscure them. No new label registry or display-shaped data.
- `sync()` keeps applying the same padded viewport rectangle per match. Box: existing 3 CSS px rounded outline (5 px outer radius), no fill, painted on an absolutely positioned `inset:0` shape child; the box's `draw` SVG stroke instead uses a rect inset 1.5 px with rx/ry 3.5 px, giving the same 5 px visual outer radius. Circle: an ellipse inscribed inside that rectangle, 3 px stroke/no fill; an SVG child with `viewBox` updated from measured width/height and ellipse coordinates inset by half the stroke, `vector-effect:non-scaling-stroke` and `pathLength=1` for draw. Every mark's shape is a child of its positioned wrapper and its badge is a sibling; neither the shape's clipping nor its blend effect can cover the badge. Underline: 3 px horizontal stroke along the bottom *inside* the padded rectangle, with its bottom edge 2 CSS px above the box bottom (so pad remains meaningful); no top or side strokes. Highlight: fill the padded rectangle with the chosen color at 0.35 opacity using `mix-blend-mode:multiply`, with no border, so dark text remains readable under the above-page overlay. Keep badges outside the blended shape. Zero-size targets behave like existing marks; no new target rejection or redaction changes.
- Page-side one reveal-keyframe builder and one animation starter for existing nodes, not a second runtime. `fade`: opacity 0→1, 250 ms. `draw`: SVG normalized stroke dashoffset 1→0 for box/circle; transform scaleX(0→1), origin left, on underline/highlight, 350 ms. `pop`: scale(.85) + opacity 0→ scale(1) + opacity 1 from center, 250 ms. `slide`: translateY(12px) + opacity 0→ none + opacity 1, 300 ms. `wipe`: 73 explicit `mask-image:conic-gradient(#000 <angle>deg,transparent 0)` keyframes at 5° increments from 0 to 360, 400 ms, linear, from 12 o'clock; no `@property`/`CSS.registerProperty()` or page-global custom properties. For `draw` and `wipe`, animate only the shape child, so the badge appears immediately; on clear, hide the badge immediately and reverse the shape animation. For fade/pop/slide, animate the entire mark wrapper including badge. `none` has no animation. Keep finished marks fully visible without retained active animations: commit final CSS style and cancel finished enter animations as fade does today. Clearing cancels enter animations, removes ids from the Map immediately, and plays the *reversed keyframes* with the same duration on each exiting node/shape, removing its wrapper at completion; reverse starts at fully visible even if the interrupted entrance had not settled, consistent with current fade behavior. Non-recording and paused clears are instant. Preserve `finishClear()` as the one post-pump synchronous removal of `.pz-exiting` nodes even if Chrome has not delivered `onfinish` (no callback guard for that guard). Redaction (`reveal:'none'`) remains instant.
- The page-side `draw()` returns its actual entry duration in ms, and `clear()` returns the longest exit duration in ms (zero if none); these share the single JS reveal-duration table with the animation builder. R pumps `duration / 1000 + 0.05` seconds only when recording and unpaused and duration is positive; clear then calls existing `finishClear()`. `redact()` retains its existing return value and instant semantics. Replacements keep existing instant old-id removal before the new enter. No timer, queue, additional ordering flag, recorder changes or blocking JS Promise. Roxygen for marks/clear lists geometry, allowed/default reveals, recording/paused behavior, and reverse clear; regenerate the existing `man/` entries via `btw pkg document`.
