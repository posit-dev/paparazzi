# Annotation validation consolidation (nykf)

Signed off by orchestrator, 2026-09-29, with the amendments below.

## Problem and root cause

The three draw actions repeat choice validation and animation pumping; marks and callouts repeat badge/style checks; captions have a separate combined style error; clear has its own id check and a different JavaScript invocation. Duplicates have drifted: caption strings cannot be empty but mark/callout strings can. SPEC § Annotations/§ Captions requires caption-specific defaults and recording-only animation pumping. The issue decision requires nonempty `color` and `font_family` for all three style consumers. No JS boot string changes.

## Before → after call sites, by issue item

1. `R/annotate.R::pz_annotate()`: handmade `type` choice block → scalar `check_string(type)` then `rlang::arg_match0(type, c("box", "circle", "underline", "highlight"))`; resolve `reveal` from `type` first, then replace its handmade block with `check_string(reveal)` and `arg_match0(reveal, c("fade", "draw", "pop", "slide", "wipe", "none"))`. `R/annotate-callout.R::pz_annotate_callout()`: retain NULL → `"pop"`, then scalar `check_string()` and the same full `arg_match0`. `R/annotate-spotlight.R::pz_annotate_spotlight()`: retain NULL → `"fade"`, scalar `check_string()`, then `arg_match0(reveal, c("fade", "none"))`. No partial matching. The scalar check is needed because `arg_match0()` accepts a full vector of choices as a default and otherwise would change the old rejection of vectors.
2. `pz_annotate()` and `pz_annotate_callout()` label branches → `check_annotation_label(label)` in `R/utils-check.R`, returning `NULL`, `TRUE`, or `as.character()` of one non-NA string/number. Reject FALSE, logical NA, and vectors, retain empty label strings and the existing label error. `pz_annotate_redact()` has no label.
3. `pz_annotate()` and `pz_annotate_callout()`: `%||%` resolution from `page_stage()` and three checks → `annotate_style(ctx, color, font_family, font_size, defaults)` in `R/utils-check.R`, returning a named style list for options. `pz_annotate_caption()` in `R/caption.R`: its separate `%||%` and combined style validation → the same helper, with `defaults = list(color = "white", font_size = 20)` and font family falling through to staged `annotate_font_family`; mark/callout defaults fall through to all three stage settings. Helper validates `color`/`font_family` separately with `check_string(allow_empty = FALSE)` and font size with shared `check_annotation_font_size()` (`check_number_decimal(min = 0, allow_infinite = FALSE)` then zero-specific abort). `R/stage.R::pz_stage()`'s `annotate_font_size` branch uses this same checker, retaining NULL reset. No change to redact's independent color semantics. In `R/stage.R::pz_stage()`, reject empty `annotate_color` and `annotate_font_family` strings at assignment with `check_string(allow_empty = FALSE)` (retain NULL reset). The style helper also rejects empty strings on consumption.
4. `R/annotate.R::pz_annotate_clear()`'s inline nullable string/nonempty check → `check_annotation_id(id, allow_reserved = TRUE)`; move/extend `check_annotation_id()` from `R/annotate.R` to `R/utils-check.R`. Existing `pz_annotate()`, `pz_annotate_redact()` and `pz_annotate_callout()` continue calling it with default `allow_reserved = FALSE`. NULL and reserved `spotlight`/`caption` remain legal only for clear.
5. `pz_annotate()`, `pz_annotate_callout()`, `pz_annotate_spotlight()` each discard the `duration <- annotate_call(...)` + conditional `pump_loop()` tail in favor of `annotate_call()` doing the pump after the CDP result. `pz_annotate_redact()` already calls `annotate_call()`; it returns no positive animation duration, so remains instant. `pz_annotate_clear()` keeps its existing `pz_js()` (no second CDP call), followed by `caption_clear()` **before** `annotate_pump(ctx, duration)`, so its video time does not drift by the reverse reveal. Add only a tiny `annotate_pump(ctx, duration)` helper for the recording/positive-duration check and `pump_loop()`; call it at the end of `annotate_call()` and from clear. Handle false/NULL durations, paused/nonrecording state, and existing call-site-specific diagnostics; do not change `annotate_boot_js` or the layer initialization behavior.
6. `pz_annotate_callout()` and `pz_annotate_caption()`: `check_string(text)` + `!nzchar(text)` abort → one `check_annotation_text(text)` in `R/utils-check.R` using `check_string(text, allow_empty = FALSE)`; preserve whitespace-only strings and literal text. No nonempty-text rule for other actions.

## User-facing error-message changes to verify

- Invalid `type`: old `` `type` must be "box", "circle", "underline", or "highlight". `` → rlang `arg_match0()` choice error (e.g. `` `type` must be one of "box", "circle", "underline", or "highlight", not "bad". ``). Invalid full-list `reveal` in marks/callouts: old `` `reveal` must be "fade", "draw", "pop", "slide", "wipe", or "none". `` → analogous `arg_match0()` choice error. Spotlight invalid reveal: old `` `reveal` must be "fade" or "none" for a spotlight. `` → `` `reveal` must be one of "fade" or "none", not "bad". `` (possibly an rlang suggestion line). Wrong type/length/NA for these choices changes from the old choices-only errors to rlang's input-type/length errors; verify representative cases (including zero-length input).
- Empty staged `annotate_color`/`annotate_font_family` previously passed assignment; now the respective `check_string(allow_empty = FALSE)` errors name those arguments. Empty `color` or `font_family` for marks/callouts previously passed; now `` `color` must be a single string, not the empty string "". `` / corresponding `font_family` message. Caption empty color/family previously said `Caption style values must be nonempty and positive.`; now each names its own argument with the above rlang message. Caption zero font size previously said `Caption style values must be nonempty and positive.`; now `` `font_size` must be greater than 0. ``. The other style type/range errors remain rlang's respective check messages (including negative, infinite, NA); mark/callout/stage zero font size retains its existing message.
- Callout/caption empty `text`: old `` `text` must be nonempty. `` → `` `text` must be a single string, not the empty string "". ``. Non-string/NA text retains the rlang string checker behavior. Label error remains `` `label` must be `TRUE`, one string or one number. ``; clear empty id remains `` `id` must be nonempty. ``; reserved id error for drawing remains `` `id` must be nonempty and cannot be "spotlight" or "caption". ``. Pump consolidation has no intended error-message changes; preserve clear's optional-layer behavior.
- There are currently no annotation/caption/stage/utils-check error snapshots in `tests/testthat/_snaps/` (or `expect_snapshot*` in the mirrored test files). Inspect any snapshots changed by the test run individually and update deliberately, not wholesale; adjust the existing caption assertion looking for `"positive"` to assert the new per-argument message.
