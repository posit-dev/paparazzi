# Shiny input binding phase — em3d

Signed off: teammate-1, 2026-09-25, before feature code.

- The installed shinytest2 0.5.1 tracer resolves the caller's name unchanged by DOM ID, reads the jQuery element's `shinyInputBinding` data, preprocesses a few values, calls `binding.setValue(el, value)`, then `$(el).trigger('change')`. Shiny's bound input stores this binding on the element and its subscribed change callback forwards values through the normal Shiny input pipeline. No direct DOM assignment and no shinytest2 optional `Shiny.setInputValue` fallback. Action/file bindings are not generic setters: reject rather than feign success; files belong to `pz_set_files`.
- Module IDs are **full DOM IDs**, unchanged, as in shinytest2's `set_inputs()`: `mod-text`, never inferred `text` from the module container. Search by exact `el.id === id` among current scope roots and descendants, including each root itself. The root page searches document. No global selector that could escape scope; no CSS interpolation of the ID. Reuse `scope_root()` for pinned detach checking and `els_call()` for scoped JS, `pz_js()` for root JS; describe the current pinned scope in errors.
- Value shapes: plain scalar strings/numbers and selectize values go directly to registered `setValue`; date range is a named `{start,end}` object (accept named R list or two-element vector converted to the object); date-valued sliders accept `YYYY-MM-DD` converted to UTC epoch milliseconds as shinytest2 does. Do not invent other widget-specific workarounds. Validate R arguments via rlang; reject unsupported file/action bindings with a classed error.
- `wait = FALSE` returns immediately after change dispatch; `wait = TRUE` calls existing `pz_wait_for_shiny_idle(ctx)`. Shiny text/date change callbacks use immediate priority (cancel 250ms keyup debounce). InputBatchSender can still make idle appear before busy: test repeated updates against server-rendered output end-to-end, without adding timers, queues, flags, or changing idle. If a reproducible causal race requires these, stop and report.
- Test seams: baseline `test-wait.R` / `test-app.R` and new fixture test; deliberately red new API test before feature code. Cover root and module scope/root-self matching, missing IDs/bindings, bad arguments/non-Shiny, control UI plus server values on all widgets and repeated text updates, and ownership/log/cleanup where practical. Targeted tests only; no full suite.

## Precision audit — g5tt

Checked: `digits = NA` preserves `1.23456789`, integers remain JSON numbers, and Dates remain ISO strings; `digits = 16` exposes the binary approximation (`1.2345678899999999`). Add a fine-step numeric widget and assert both its visible value and server output at high precision.
